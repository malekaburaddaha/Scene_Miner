## Bibliography: every entry generated from fetched metadata

All 20 references in `paper/main.bib` are generated by `scripts/build_bib.py`
from records fetched over HTTPS. None is typed from memory.

| source | used for |
|---|---|
| arXiv API (`export.arxiv.org`, by id) | title, full author list, first-version date — **all 17 arXiv ids resolve to the intended paper** |
| Crossref (by DOI) | published authors, venue, year, volume, pages for 12 DOI-bearing works |
| Semantic Scholar batch API | published venue and DBLP keys (ICML / ICLR have no Crossref DOI) |
| OpenAlex | Roy & Vetterli, EUSIPCO 2007 (not indexed by Crossref) |

Raw responses: `paper/bibcheck/api_responses.json`, `crossref_by_doi.json`,
`openalex_roy2007.json`; per-entry provenance: `paper/bibcheck/VERIFICATION.md`.
DBLP was not queried directly, because it serves automated clients a bot
challenge page. The turbo-wide search for existing `.bib` files timed out after
10 minutes (exit 124), so it was inconclusive. The WACV `main.tex` uses an inline
bibliography that is itself unverified, so it was not used as ground truth.

## Official CVPR 2026 author kit

`cvpr.sty` and `ieeenat_fullname.bst` are cloned from
`github.com/cvpr-org/author-kit` (commit 2917585, "CVPR 2026 Paper Template"),
in `[review]` mode with `pagebackref`. The kit requires `silence` and
`cleveref`, which the cluster TeX installation lacks. Both were fetched from CTAN
and are placed beside the paper; `silence.sty` came prebuilt and `cleveref.sty`
was generated from its official `.ins/.dtx`.

## Page budget

`paper/main_cvpr.pdf` is 10 pages. **Main text fills pages 1–8**: the last
paragraph ends at the bottom of page 8's right column. **References start at the
top of page 9.** There are no LaTeX errors, no undefined references or
citations, no BibTeX warnings, and no overfull box above 10 pt.

The extra space went to content, not padding:

* SceneMiner presented as one model (the v2.4 gate) throughout. Earlier versions
  appear only as rows in the history parts of Tables 1 and 3.
* A training-only gate table (Table 3), showing that the "no test data" claim is
  inspectable.
* A three-regime table with late-fusion controls (Table 8) and the honest
  conjunction result.
* A single-rater sensitivity table (Table 9) and a per-attribute robustness
  table (Table 10), because the in-domain lead is uneven and the paper says so.
* The val150 retrieval-to-breakage table re-run with SceneMiner v2.4 (Table 12).
* A reproducibility paragraph.

## Figures

All regenerated for the single model. **Every qualitative figure is now balanced
across datasets, as requested:** Figure 2 and the supplementary strips show
exactly two retrievals per corpus (nuScenes, Waymo, BDD100K), each ranked within
its own corpus, so no dataset dominates. Figure 2 has 8 nuScenes, 8 Waymo and 8
BDD100K images. With the contrastive gate, the semantic strips now retrieve the
requested objects ("large truck or bus ahead" returns trucks and buses in all
three corpora) rather than the rainy scenes the prompt-gated version returned.
Figure 4(b) now plots the three human-graded regimes against the two
no-learning fusion controls.

## Re-run for the unified model

`results/cvpr/milestone20_val150_retrieval_v24.json`. SceneMiner's top-25 for the
62 degradation queries: front mAP −0.057 (p = 0.002), VRU recall −0.196
(p < 0.001); harder than SigLIP2 (mAP −0.026, p = 0.010); indistinguishable from
the VLM lookup. Night/rain metadata retrieves scenes with significantly more
ghost false positives (+0.028, p = 0.028).
